## 0. 요약

**무엇이 바뀌나.** 지금 구현은 정답을 숨기고 여러 번 재시도시켜 보상으로 학습한다. 새 구현은 다음과 같다. `[사용자]`

1. 모델이 문항을 한 번 푼다.
2. V8 파서가 채점한다.
3. 모델이 정답을 직접 보고 오답노트와 고쳐 쓴 풀이를 쓴다. 맞힌 문항도 쓴다.
4. 문제·답·노트를 함께 학습한다.
5. 노트가 "이미지를 잘못 봤다"고 하면 Vision 조정층까지, 아니면 LLM 조정층과 Merger만 갱신한다.

**시험 순서.** 300문항 학습 → 예전에 틀린 342문항 재풀이 → 통과하면 3,417문항 학습. `[사용자]`

**비용.** 잔액 48.24달러(50.42달러 − 런포드 청구 2.18달러), 예비금 5달러를 빼면 43.24달러를 쓸 수 있다. 전체 예상은 동시 생성 속도에 따라 **9~37달러**다 `[추정]`. 첫 대여기에서 속도를 재고 다시 계산한다.

**기대치를 먼저 분명히 한다.**
- 가까운 논문에서 모델이 쓴 수정 데이터를 지도학습한 첫 풀이 변화는 **−0.2 ~ +2.8점**이다(SCoRe) `[외부]`. 상위 모델이 만든 점검 데이터까지 넓히면 **−4.7점**까지 떨어진 예도 있다(Learning to Check). 가장 비슷한 MMMU 실험의 지도학습 대조군은 **+0.41 ~ +2.19점**이다.
- 그래서 62점에서 67점까지 오른다는 근거는 없다. 900문항의 표준오차는 약 1.6점이다.
- 같은 데이터로 직접 비교한 논문에서는 강화학습이 지도학습을 이긴 경우가 3건 중 2건이다. 다만 그 실험들은 데이터 수만 건, H100 8장 규모라서 우리 예산으로는 재현할 수 없다.
- 지난 답변에서 "정답을 보는 방식이 더 낫다"고 한 말은 이렇게 고친다. **이 예산 안에서 실제로 끝낼 수 있고 사용자 의도에 맞는 방식**이지, 성능이 더 잘 오른다고 증명된 방식은 아니다.

**통과 기준 한 가지.** 틀렸던 342문항은 학습 없이 다시 풀기만 해도 일부 맞는다. 실측 비율은 약 24%다(§6.3). 그래서 "맞는 게 생겼다"가 아니라 **같은 조건으로 다시 푼 미학습 모델보다 우연 범위를 넘게 많이 맞혔는가**로 판단한다.

### 3.1 노트 프롬프트 초안 `[설계]`

이미지를 먼저 넣고 글을 마지막에 두는 형식은 P0와 같다.

```text
{P0 문제 글}

Your earlier solution:
{첫 풀이 원문}

Grading result: {CORRECT | WRONG | NO CLEAR FINAL ANSWER | CUT OFF}
Correct answer: {정답}

Review your own work like a student writing an error note.
Use these headings in this order, each starting on a new line.

What the image shows: list the facts this problem needs, checking each one against the image.
Image reading: CORRECT, MISREAD or UNSURE. Write MISREAD if your earlier solution used a fact the image does not show, even if its final answer was right.
Cause: IMAGE, REASONING, KNOWLEDGE, CALCULATION, NO_FINAL_ANSWER or NONE.
What went wrong: the exact step and why. If nothing went wrong, say what was done properly.
How to solve it: the method to use on similar problems.
Corrected solution: one complete solution from the beginning. Keep the parts of your earlier solution that were right and fix it from the first mistake on. Do not mention this note, an earlier attempt, a grade or being told the answer. End with "Final answer: ...".
```

JSON으로 출력시키지 않는다. 예전 JSON 노트는 필드 누락과 빈 응답이 반복됐다 `[실측]`. 학습 파일은 JSONL로 저장하므로 "JSON으로 학습"하는 형태는 유지된다.

### 3.2 파싱과 학습 행 만들기 `[설계]`

**행 B (노트 학습).** 입력은 노트 프롬프트, 출력은 "Corrected solution:" 앞까지의 노트다. 모든 제목이 있고 자연 종료된 노트만 쓴다. 자기 풀이는 입력에만 있고 손실에서 제외한다.

**행 A (풀이 학습).** 입력은 P0와 이미지, 즉 평가와 같은 입력이다. 출력은 다음 순서로 정한다.

1. 첫 풀이가 정답이고 `Image reading: CORRECT`이면 → **첫 풀이 원문**
2. 그 외 → **고쳐 쓴 풀이**
3. 둘 다 아래 조건을 못 넘으면 → 행 A를 만들지 않음

행 A의 출력 조건은 모두 만족해야 한다.

| 조건 | 이유 |
|---|---|
| 자연 종료 | 잘린 글을 정답처럼 배우지 않게 |
| V8 추출 답이 정답과 일치 | 틀린 풀이를 배우지 않게 |
| 32토큰 이상 | **답만 있는 출력 금지.** G6에서 답만 배우자 출력이 짧아졌다 (§4.3) |
| 4096토큰 이하 | 장황한 풀이를 배우지 않게. 평가 상한 8192와는 별개 |
| 같은 12토큰 구간이 3번 이상 반복되지 않음 | 반복 생성을 배우지 않게. 논문의 경고 반영 (§4.1) |
| **고쳐 쓴 풀이에만 적용:** "earlier solution", "earlier attempt", "previous attempt", "grading result", "was told", "this note", "error note", "given answer" 같은 표현 없음 | 평가 때 없는 상황을 말하지 않게. "correct answer", "note", "grade"는 정상 풀이에도 흔해 넣지 않는다. 예전 정답 응답 558개 중 360개(64.5%)가 "correct answer"를 포함한다 `[실측]` |

빠진 행은 이유와 함께 모두 기록한다. 빠졌다고 다른 문항으로 **교체하지 않는다**.

### 3.3 학습 경로 `[사용자]`

- `Image reading: MISREAD` → **전체 경로**: Vision 조정층 + Merger + LLM 조정층
- `CORRECT` 또는 `UNSURE` → **LLM+Merger 경로**: Vision 조정층에 기울기 없음
- 노트가 파싱되지 않으면 학습에 쓰지 않음

코드에는 이미 문항별로 Vision을 켜고 끄는 `VisionRoute`가 있다(`policy.py:49-50`). 켜고 끄는 값이 모델 전체에 적용되므로 작은 묶음은 경로별로 나눈다.

이 판단은 **모델의 자기 신고**다. 공개 데이터에는 실제로 잘못 봤는지 확인할 정답이 없다. 경로별 문항 수를 보고하고, 보고서에는 "실제 시각 오류"가 아니라 "자기 신고 경로"로 쓴다.

## 4. 참고 논문과 응용

아래 수치는 조사 담당이 원문 또는 전체 글에서 읽었고, 그중 STaR, SCoRe, SCL, OpenVLThinker, CoTErrorSet, Learning to Check 등 핵심 수치는 저장된 원문 글에서 다시 대조했다. 논문 간 점수는 조건이 달라 직접 비교할 수 없다. 대부분은 글자 전용 또는 다른 모델 실험이다.

### 4.1 실제로 응용하는 것

| 논문 | 한 일과 결과 | **우리가 가져온 것** | 가져오지 않은 것 |
|---|---|---|---|
| **STaR** (Zelikman 2022) | 정답을 힌트로 주고 풀이를 쓰게 한 뒤, 힌트 없는 입력으로 학습. CommonsenseQA 68.8→72.5, GSM8K 10.1→10.7 | **학습 입력에서 정답 제거**(행 A), 정답에 도달한 풀이만 사용 | 수십 회 반복. 예산 밖 |
| **Constitutional AI** (Bai 2022) | 응답→비평→수정→수정본 학습. 비평이 부정확해도 수정본은 개선 | **수정본을 학습 목표로**, 비평은 풀이 목표에 넣지 않음. 일반 표본을 섞어 기존 능력 유지 → **맞힌 문항의 풀이를 행 A에 포함** | 해로움 지표. 정확도와 무관 |
| **ISC** (Han 2024) | 오답 토큰에 손실을 주지 않는 부분 마스킹. CuteGPT-13B 첫 답 37.2 → 자기수정 후 42.0 | **틀린 풀이는 입력에만, 손실 제외** | gpt-3.5 풀이 사용 |
| **CoTErrorSet** (Tong 2024) | 정답과 자기 오답을 보고 원인을 쓰게 한 뒤 학습. Flan-T5-large MathQA 42.79→48.95 | **정답을 본 원인 작성 구조.** 가장 비슷한 방식 | PaLM2가 원인 작성(우리는 모델 자신), 오답을 목표에 넣는 것 |

| **OpenVLThinker** (Deng 2025) | 자기 개선 반복. 첫 지도학습 68.5→57.5, 반복 구간을 잘라내니 63.4 | **반복 든 목표 제거.** 지도학습이 먼저 점수를 떨어뜨릴 수 있다는 경고 | QwQ 풀이, 강화학습 반복 |

### 4.2 응용하지 않는 것과 이유

- **평가 때 쓰는 방식이라 금지:** LEAP, Reflexion, Self-Refine, Mistake Notebook Learning, M2Note. 이름은 오답노트와 가장 가깝지만 추론 때 노트를 넣는 방식이다. 수업 자료 19쪽의 프롬프트 쪽 방법이라 해결책이 될 수 없다. M2Note는 Qwen3-VL-8B MMMU에서 67.1→68.4를 보고했다.
- **상위 모델 의존이라 금지:** Learning to Check(GPT-4), S2R, LLaVA-CoT(GPT-4o), Vision-R1(DeepSeek-R1), GPRO(GPT-4 분류), Octopus의 초기 학습(Qwen3-VL-30B).
- **강화학습 규모 초과:** SCoRe, VL-Rethinker, MM-Eureka, Octopus. Octopus는 Qwen3-VL-8B로 MMMU 62.0→72.4지만 H100 8장 규모다.
- **나중 후보:** PAPO의 이미지 가림 비교. 이미지를 가려도 답이 같으면 이미지를 안 본 것이므로 자기 신고를 싸게 확인할 방법이 될 수 있다. 추가 생성이 필요해 이번에는 넣지 않는다.

### 4.3 이 방식에 불리한 근거

숨기지 않고 적는다.

1. **첫 풀이 효과가 작거나 음수다.** SCoRe 지도학습 −0.2~+2.8, Learning to Check −0.3과 −4.7(GPT-4 데이터), OpenVLThinker 첫 지도학습 −5.1(잘라낸 뒤), −11(원본).
2. **강화학습이 이긴 사례가 있다.** MM-Eureka 평균 64.5 대 57.7, SCoRe 첫 풀이 60.0 대 최대 55.4. OpenVLThinker에서는 거의 같았다(71.3 대 71.1).
3. **한 번 통과는 얕다.** 정답 힌트로 쓴 자기 풀이를 한 번 학습해 시각 언어 모델 정확도를 올린 논문은 찾지 못했다. STaR의 성과는 수십 회 반복에서 나왔다.
4. **노트의 시각 판단을 검증한 논문이 없다.** 시각 비평은 추론 비평보다 약하고(VISCO), 사람 전문가도 원인 분류에 품이 든다(MMMU). 그런데 이 신호가 Vision 학습을 결정한다.
5. **정답을 보면 끼워 맞출 수 있다.** 모델은 힌트를 쓰고도 잘 밝히지 않는다(Turpin 2023, Chen 2025). 파서는 최종 답만 보므로, 정답에 맞춘 거짓 이미지 해석이 학습 목표로 들어갈 수 있다. 이 부분은 논문을 근거로 한 제 추론이다.
6. **Vision 학습이 해로웠던 기록이 있다.** G6의 Vision 조건은 60문항에서 36→21개로 가장 낮았고 새로 맞힌 문항은 0개였다 `[실측]`.
7. **노트 학습 효과가 평가로 이어지지 않을 수 있다.** 노트는 평가 때 없다. 노트 쓰기 학습이 첫 풀이에 도움이 된다는 증거는 엇갈린다.

**우리 과거 실패와 다른 점.** G6는 행당 목표가 평균 21토큰인 사실상 답만 있는 학습이었고, 학습 후 출력 중앙값이 720→8토큰으로 무너졌다(LLM 조건) `[실측]`. 이번 목표는 풀이 전체이고 32토큰 미만은 막는다. 다만 G6 분석 문서도 인과를 입증하지 못했다고 적었다. 정답→오답 19개는 모두 정상 종료·파싱된 응답이었으므로 **짧아진 것만이 원인은 아닐 수 있다**. 그래서 평가에서 출력 길이를 반드시 함께 본다.

### 5.5 새로 필요한 조각 세 가지

1. **연속 투입 생성기.** 기존 `VLLMRolloutEngine.sample_with_settings`는 한 번에 받은 묶음이 전부 끝나야 돌아오고, 기존 일치 검사도 통과해야 한다. 묶음을 잘게 나누면 묶음마다 가장 긴 응답을 기다리느라 놀게 된다. 그래서 `src/mmdl/evaluation/backends/vllm_backend.py:302,317`의 `add_request`/`step` 방식을 약 40줄로 옮겨, 끝난 자리에 바로 다음 문항을 넣고 결과를 바로 저장한다.
2. **문항 여러 개 묶음 학습기.** 현재 학습 코드는 문항 1개씩만 받는다(`policy.py:147-150`, `train.py:119`). 길이가 비슷하고 경로가 같은 행을 묶는 패딩 처리를 새로 만들고, 1개씩 돌린 결과와 손실·기울기가 같은지 CPU 시험으로 확인한다.
3. **로컬 생성의 presence penalty.** `GeneratedOnlyPresencePenalty`는 `src/mmdl`에만 있어 폴더 단독 실행을 막는다. 작은 클래스이므로 새 폴더로 복사한다.

### 5.6 정답·금지 데이터 격리

- **첫 풀이 프로세스:** 정답 파일 접근 금지(`allow_vault=False`). 채점은 격리된 채점 서비스가 한다. 정답 파일 열기는 프로세스 안 감사 훅으로 막고, 프롬프트에 정답이 없음을 시험으로 확인한다. 운영체제 수준 격리는 아니다(`guards.py:1`).
- **노트 프로세스:** 별도 프로그램으로 실행하고 정답을 읽는다. 모델을 한 번 더 불러오는 비용(약 2분)보다 격리가 낫다.
- **학습 프로세스:** 수집 결과 파일만 읽고 정답 파일을 열지 않는다.
- **모든 학습 단계:** MMMU·MMMU-Pro 경로 차단, 상위 모델 라이브러리 차단(`allow_benchmark=False`). 평가 단계와 프로세스를 섞지 않는다.
- 평가 결과에는 `training_allowed=false`를 찍는다.

### 5.7 동결 승인 절차

이전 경로의 동결 승인(`package-root-vN`, approval export, `code_hashes`)은 새 경로에서 쓰지 않는다. 고칠 때마다 다시 만드느라 시간이 많이 들었고, 내보내기 도중 로컬 학습과 충돌했다 `[실측]`.

| 유지 | 잃는 것과 대신하는 것 |
|---|---|
| 작업 내용 해시와 승인, 고정 커밋 clean clone, 고정 의존성 잠금과 실제 설치 비교, 모델 해시, 데이터 묶음 해시와 `pool_freeze.verify`, 평가 격리, 감시자, 실행 계획 해시 | 실행 때 데이터 승인 재검증 → **문항 목록 해시를 작업 파일에 고정**, `binding.code_sha256`에는 커밋 문자열의 SHA256 |

저장 코드의 조건도 지킨다. `checkpoint.py:42-47`은 4개 묶음 값이 모두 64자리 16진수여야 하므로 40자리 커밋을 그대로 넣으면 거부된다. 커밋은 `export_for_eval(code_commit=)`로 따로 넘긴다. 평문 설정에는 `sha256, prompts_sha256, initial_checkpoint, image, model.lora, model.modules_to_save, expected_trainable, optimizer`가 필요하다.

| L1 | 독립 검토 | 차단 결함 없음 |
| L2 | 실제 모델 2문항 | 실제 풀이·노트 → 갱신 1회 → LLM·Merger 변경 → 저장 → 새 프로그램 재로딩 일치. Vision은 전체 경로일 때만 변경 |
| L3 | 실제 모델 10문항 | L2와 같은 항목 + 경로별 문항 수 기록 |

- 로컬 결과는 **작동 증거일 뿐 성능 증거가 아니다**.
- 8GB에서 긴 행이 메모리를 넘으면 로컬 전용 행 길이 제한을 기록과 함께 쓴다. 런포드에는 적용하지 않는다.
- 응답이나 노트를 만들어 넣어 경로를 시험하지 않는다. 한쪽 경로가 실제로 안 나오면 "미검증"으로 남긴다.

### 6.3 300문항 통과 기준

사전에 고정한다.

- **통과:** 노트 포함의 seed 평균 정답 수가 F0보다 **6.5문항 이상** 많거나, **3개 seed 모두** F0보다 많음. 자동으로 3,417문항으로 간다.
- **애매:** 평균은 F0보다 많지만 통과 기준에는 못 미침. 멈추고 결과를 보여 드린 뒤 진행 여부를 묻는다.
- **멈춤:** 노트 포함 ≤ F0. 3,417문항으로 가지 않고 원인을 분석해 보고한다.
- **붕괴 경보:** 노트 포함의 출력 토큰 중앙값이 F0의 절반 미만이거나, 최종답 없음 또는 8192 도달이 늘면 점수와 관계없이 보고하고 묻는다.
- **본안은 노트 포함으로 미리 정한다.** 노트 제외가 더 높아도 자동으로 바꾸지 않고 보고한 뒤 묻는다. 바꾸면 같은 342문항으로 고르고 다시 평가하는 셈이라 편향이 있음을 함께 적는다.

**이 시험의 힘에는 한계가 있다.**
- 예전에 R1에서 틀린 473문항 중 R2에서 맞힌 수는 112개(약 24%)다 `[실측, 조건 다름]`. 같은 비율이면 F0 재실행만으로 342문항 중 약 80개가 맞는다. 그래서 "맞는 게 생긴다"는 거의 항상 참이다.
- 우연으로 인한 차이는 1 seed 약 ±11문항, 3 seed 평균 약 ±6.5문항이다 `[추정: 독립 가정]`. 300문항 학습의 효과는 이보다 작을 수 있다.
- 단순히 "평균이 더 높음"만 보면 효과가 전혀 없어도 약 50%로 통과한다. 그래서 여유를 뒀고, 효과가 없을 때 우연히 통과할 확률은 약 20%다 `[추정]`.
- 이 기준은 **성능 향상 증명이 아니라 돈을 더 쓸지 정하는 문턱**이다. 통과해도 "개선됨"이라고 쓰지 않는다.

| 순서 | 내용 |
|---|---|
| R8 | 설치, 해시 확인, 1차 수집·F0 결과 업로드 |
| R9 | 나머지 3,117문항 수집 (30분마다 로컬로 내려받기) |

### 6.5 최종 보고 방식

- **주 비교:** 같은 조건의 F0 대 학습 모델, 같은 문항, 같은 seed. V8 하나로 채점한다.
- **보고 항목:** seed별·평균 정답 수, 문항별 득실, 과목별 정확도, 최종답 없음, 8192 도달, 출력 토큰 중앙값, 경로별 문항 수, 빠진 행 수와 이유, 시간, 메모리, 실제 비용.
- **62점과의 관계:** 62점은 32K와 큰 이미지 조건이므로 참고 값으로만 나란히 적고 조건 차이를 명시한다.
- **개선 주장:** 342문항에서 seed 평균 차이가 우연 범위(표준오차 2배, 약 13문항)를 넘고, 900문항 점수도 F0보다 높을 때만 한다. 작은 표본을 MMMU 전체 개선으로 일반화하지 않는다.
- **MMMU test와 MMMU-Pro 평가**는 이 계획 범위 밖이다. 별도 승인 후 진행한다.

## 7. 런포드에서 최대한 빠르게

### 7.1 먼저 분명히 할 것

**빠른 생성기(vLLM)는 생성 전용이다. 역전파를 못 한다.** "빠른 생성기로 여러 문제를 동시에 학습"은 불가능하다. 그래서 다음처럼 나눈다.

- **풀기·노트 쓰기:** 빠른 생성기로 여러 문항 동시에
- **학습:** PyTorch로 여러 문항을 묶어서

**CPU로 모델 계산을 돕는 것도 불가능에 가깝다.** A40 대여기는 9코어, 메모리 50GB다 `[실측]`. 그래픽카드가 약 20ms에 끝내는 한 걸음이 CPU에서는 수백 배 걸린다 `[추정]`. CPU와 메모리는 그래픽카드가 놀지 않게 준비 일을 맡는 것이 최대 활용이다.

### 7.2 가장 큰 효과: 생성과 학습 분리

지금 경로는 학습 모델과 빠른 생성기를 같은 그래픽카드에 올리고 갱신마다 가중치를 맞췄다. 메모리를 나눠 쓰고, 시작에만 333초가 걸렸고 `[실측]`, 1단계 실패 원인도 이것이었다(여유 35.22GiB < 요구 35.54GiB). 새 경로는 **생성을 전부 끝낸 뒤 학습**하므로 각 단계가 그래픽카드 전체를 쓴다.

### 7.3 그래픽카드 설정

| 항목 | 값 | 근거·효과 |
|---|---|---|
| 동시 처리 수 | **32, 48, 64를 측정해 결정** | 현재 실측은 평균 2.7개 동시, 134토큰/초. 한 걸음 약 20ms `[실측]` |
| KV 메모리 | 약 26~30GiB, 19만~22만 토큰 | 사용 가능 44.42GiB × 0.9 − 모델 8.68GiB − 예비. 8GiB = 58,240토큰 `[실측]` |
| 평균 동시 수용량 | 약 40~50개 `[추정]` | 시간 가중 평균 문맥 4,327토큰(예전 900문항, 큰 이미지). 342문항만은 4,828토큰이고 노트 프롬프트는 약 1.4K 더 길다. 넘으면 다시 계산하느라 느려지므로 측정 필요 |
| `max_num_batched_tokens` | 수집 16384 이상 | 기본 8192. 공식 문서가 처리량을 위해 8192 초과 권장 `[외부]`. 평가에도 필요하면 `proof_eval.py:249-256` 래퍼로 넣는다. `src/`는 고치지 않는다 |
| `enforce_eager` | 수집은 False로 측정 | 끄면 빠르고 메모리를 더 쓴다 `[외부]`. **평가는 기존 코드의 True 유지** |
| 연속 투입 | 끝난 자리에 바로 다음 문항 | 묶음 대기 낭비 제거 (§5.5) |

측정 방법: 수집 시작 뒤 각 값으로 5분씩 돌리며 초당 토큰, 재계산 횟수, 그래픽카드 사용률, 최대 메모리를 기록한다. 결과는 버리지 않는다. 평가의 동시 처리 수는 한 값으로 고정하고 F0와 학습 모델에 똑같이 쓴다. 제출 보고서의 동시 2와 다르지만 F0를 같은 조건으로 다시 재므로 비교는 공정하다.

**평가 토큰의 75%는 끝나지 않는 응답이 쓴다.** 342문항 중 106개가 8192에 닿고, 이것만 약 87만 토큰으로 전체 116만의 75%다 `[실측]`. 상한은 고정이므로 줄일 수 없지만, 학습으로 반복이 줄면 평가 시간도 준다.

여러 모델을 한 그래픽카드에 동시에 올려 평가하지 않는다. 한 엔진에 동시 처리를 몰아주는 편이 묶음 효율이 높고 KV도 더 쓸 수 있다 `[추정]`.

### 7.4 학습 속도

| 방법 | 내용 | 상태 |
|---|---|---|
| 그래디언트 체크포인팅 끄기 | 48GB에 들어가면 끈다. 계산을 다시 하지 않아 빨라짐 | 측정 필요. G6는 켠 상태로 최대 14.7GB(`recovered/g6-full-*/pilot_*`, 조사 담당 계산) |
| 길이·경로별 묶음 | 토큰 예산 안에서 비슷한 길이끼리. 경로가 같아야 함 | 새 코드 (§5.5) |
| 묶음 효과 측정 | 1개씩 대비 1.5배 미만이면 1개씩으로 되돌림 | 측정 필요 |

학습 비용은 전체에서 작은 편이다. G6 기준 초당 약 1,047토큰(입력 8,374,856토큰 ÷ 7,998초, `g6_full10k_final_analysis_20261005.md`)으로 3,417문항에 약 3.8시간(약 2.4달러) `[추정]`이다. G6는 행당 목표가 21토큰이라 이번과 다르므로 첫 대여기에서 다시 잰다.

### 7.5 CPU와 메모리 활용

| 일 | 방법 |
|---|---|
| 이미지 처리 | 8개 프로세스로 미리 읽고 크기 조정해 메모리에 둔다. 공식 문서상 오프라인 `LLM`은 이미지 전처리를 한 줄로 처리하므로 미리 해 두는 것이 낫다 `[외부]` |
| 채점 | 끝난 응답을 프로세스 풀에서 V8 채점 |
| 학습 데이터 준비 | `DataLoader` 작업자 8개, 메모리 고정, 미리 가져오기 |
| 병합 모델 | `/dev/shm`에 저장해 디스크 대기 없이 불러오기 (약 8.5GB). 크기가 모자라면 디스크 사용 |
| 해시 확인 | 여러 프로세스로 동시에 |

매분 그래픽카드 사용률과 CPU 사용률을 기록한다. 생성 중 그래픽카드 사용률이 85% 아래면 CPU가 병목이므로 원인을 찾는다. 사용률이 실제로 높아지는 것을 목표로 삼고, 수치는 실측으로 보고한다.

### 7.6 돈 아끼는 나머지

- **재사용:** 300문항 수집과 F0 평가는 2차에서 다시 하지 않는다.
- **모델을 다시 불러오는 횟수 최소화:** 같은 모델의 seed 3개는 묶어 실행한다.
- **단계를 한 대여기에 묶기:** 설치 약 15분(약 0.16달러)이 들지만, 기다리는 시간에 대여기를 켜 두지 않는다.
- **사전 거르기 삭제:** 3,417 × 4회 측정이 사라진다. 이것만으로 약 46시간(이전 순차 추정)이 없어진다.
- **채택하지 않음:** 반복을 감지해 일찍 끊기. 평가 조건과 달라지므로 평가에는 쓸 수 없고, 수집에서의 절약도 작다.
