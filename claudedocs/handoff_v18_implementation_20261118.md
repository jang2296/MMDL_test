# v18 구현 및 Claude Code 인계

## 적용 범위

v18은 지정된 Qwen3-VL-4B-Instruct F0에서 시작한다. 본학습 부모 3,000개마다 정답 없는 첫 풀이 한 번, 적격한 자기 관측·노트 각각 최대 한 번, 누설 검사를 통과한 교훈으로 재풀이 최대 한 번을 사용한다. 최종 평가는 P0·BF16·B2 샘플링·문항별 seed·공식 프로젝트 V8로 900개 문항마다 답 하나를 생성한다. 보완 판정 점수는 별도로 보고한다. 조정층 강도는 1, 학습 경로는 Vision LoRA·Merger·LLM LoRA, 평가 동시 수는 9다. 그룹 RL, 출처 교체, 강도 보간은 이번 범위에서 제외됐다.

## 인계 후 확인 순서

1. `fine_tuning/error_note/README.md`의 `v18_data prepare`를 과거 작업공간 없이 빈 캐시에서 실행한 뒤, 두 번째 출력 경로에서 같은 캐시를 재사용한다. `validation.json`의 3,000/512/200/128/16, 논리 해시·이미지·순서와 `execution.json`의 출처별 파일 전송량·변환 시간·공유 파일·전체 경과를 비교한다. 23GiB 로컬 환경에서 다른 진단과 전수 복원을 병행한 한 시도는 메모리 할당 오류로 종료됐다. 변환기는 원 행 캐시를 검증 직전에 해제하도록 했고, 마지막 전수 복원과 GPU 진단은 순차 실행했다. 효과 집합 128개는 노출 이력이 불완전하여 독립적인 성능 개선 증거로 집계하지 않는다.
2. 게시 대상으로 선별된 코드와 공개 recipe를 Claude Code가 검토한다. 외부 포드 실행 스크립트는 로컬 묶음 업로드를 제거하고 고정 commit, 같은 캐시 경로, 기존 uv 환경, 초기 다운로드 속도 기록과 회수 경로를 사용한다. 코드 안의 `v18-train` 명세는 자료 준비에서 시작한다.
3. 학습 체인은 자료 검증 → 준비 생성·SFT → BF16 기능 검사 → 본학습·마무리 → 외부 비교·재로딩·비병합 내보내기·봉인 순이다. 초반 실제 생성에서 지원 부모 수, 자력/위치제공별 검증 성공, N 토큰·기울기·저장 갱신을 함께 확인한다. N이 끝까지 0이면 자기 오류 교정 학습이 실제로 일어났다고 보고할 수 없다.
4. 평가용 params에는 해당 평가에 대한 실제 사용자 결정과 학습 봉인을 기록한다. 평가 전 시각 훅 대조, 9칸 KV 용량과 처리량 검증을 통과한 뒤 단일 등록으로 평가한다. 중단 시 같은 params로 `plan resume-evaluation`을 사용한다. V8 점수와 CompassVerifier 보완 점수는 별도로 회수한다. 목표 판정은 V8 585/900이다.
