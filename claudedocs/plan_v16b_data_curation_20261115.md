## 1. 절대 규칙

1. **MMMU·MMMU-Pro의 모든 split과 파생물은 학습 자료가 될 수 없다.** 이름이나 카드에 MMMU·MMMU-Pro·MMStar·MathVista·MathVerse가 들어간 혼합 자료, 각 출처의 val·test split도 제외한다.
2. **MMMU 문항 내용은 오염 판정에서만 본다.** 개별 MMMU 문항이나 우리 B2 개별 결과(어느 문항을 틀렸는지)를 보고 비슷한 학습 문제를 고르거나 만들지 않는다. 선정에 쓸 수 있는 벤치마크 정보는 **공개된 30과목 목록과 이미지 유형 범주**뿐이다.
3. **상위 모델(GPT·Claude·Gemini 등)이 쓴 질문·답·풀이·주석은 쓰지 않는다.** 데이터셋이 직접 제공한 사람 작성 풀이만 허용한다(2026-11-11 결정). 출처가 불명확하면 제외한다.
4. **우리가 문제를 새로 만들거나 바꾸지 않는다.** 2026-10-30 결정에 따라 합성 생성기와 변형은 쓰지 않고, 기존 공개 자료의 원 문항만 쓴다.
5. **오염 검사 기준을 완화하지 않는다.** 기존 12단계 검사(§6)를 그대로 쓴다. DUPLICATE·UNRESOLVED 후보는 같은 계열(family)까지 제외한다.
6. **AI 검토는 사람 검증이 아니다.** Codex가 직접 본 판정은 `reviewed_by="codex-ai"`, `human_verified=false`로 기록한다.
7. **기존 보류분은 계속 제외한다.** hf-pool-v3 dev 402·sealed 209, Geometry3K 보류 5+5, v10 `HELD_OUT_*`, 그리고 §8에서 감시용으로 지정하는 문항과 그 계열이 여기에 해당한다.
8. **결과를 보고 목록을 바꾸지 않는다.** 동결 뒤에는 학습 결과를 보고 문항을 교체하지 않는다.

## 4. 점수와 거르기

### 4.1 하드 필터 (하나라도 해당하면 제외, 이유 코드 기록)

- 오염 영수증 없음·불완전(`NO_RECEIPT`), 보류분 계열(`HOLDOUT_FAMILY`)
- 채점 불확실(`UNGRADABLE`): 자유 서술 답, 정답 표기 모호
- 그림 없음 또는 읽기 어려운 그림(`NO_IMAGE`, `ILLEGIBLE`)
- 상위 모델 관여 필드(`TEACHER_FIELD`), 출처 불명(`UNKNOWN_PROVENANCE`)
- 같은 계열의 두 번째 이후 항목(`DUPLICATE_FAMILY`) — 계열당 1개
- 정답 오류가 확인된 항목(`LABEL_ERROR`, §5 검토에서 발견)
- 권리 보류(`RIGHTS_PENDING`) — 라이선스가 불명확한 새 수집 자료(§7)에만 적용. AI2D는 해당 없음(포함 결정)

### 4.2 그림 필요성 (`image_needed`)

- **필요**: 질문이 그림 속 값·라벨·위치·모양·관계를 묻는다("in the figure/graph/table", "shown", "according to the chart", 그림 속 기호·라벨 참조). 또는 데이터셋이 그림 기반 과제다(차트·지도·악보·조직·심전도·도형 계산).
- **불필요 의심**: 질문 문장만으로 계산·상식으로 답이 정해진다. 그림은 장식이거나 문장을 반복한다. ScienceQA에서 그림이 단순 장식인 유형이 여기에 해당한다.
- 규칙으로 정하고 §5에서 출처별 정밀도를 잰다. 불필요 의심은 점수를 크게 깎되, 정밀도가 낮은 규칙(80% 미만)은 쓰지 않는다.
- 그림을 빼고 모델에게 실제로 풀게 하는 검사(블라인드)는 생성 비용 때문에 이번에 하지 않는다. 구현해 두었다면 쓰되, 결과는 자료 선정에만 쓰고 학습에는 넣지 않는다.

### 4.3 MMMU·MMMU-Pro 관련성

- **과목 범위**: MMMU 검증셋은 30과목이 30문항씩 같은 비중이다. 학습 자료가 소수 과목에 몰리지 않도록 과목별 하한·상한을 둔다. 자료가 없는 과목은 `REPORT.md`에 "자료 없음"으로 적는다. §7의 새 수집 후보로만 다루고, 다른 과목 문항으로 채우지 않는다.
- **추론 깊이**: 2단계 이상 추론·계산이 필요한 문항을 우선한다. 한 단계 인식(이름 맞히기, 개수 세기)만 하는 문항은 출처별 상한을 둔다.
- **형식**: MMMU-Pro는 10지선다다. 보기가 많은 객관식을 일정 비율 확보하되, 보기를 늘려 문항을 바꾸지는 않는다(규칙 4).
- **수준**: 대학·고교 수준을 우선한다. 초중등 문항은 그림 읽기 기능(표·차트·도식 해석)을 기르는 경우만 남긴다.

### 4.4 배울 여지 (`f0_prior`)

- 원본 모델(또는 학습 전에 가까운 모델)이 정답 없이 푼 기록을 찾는다. 후보 원천은 다음과 같다.
  - 1판(2026-11-01~02) hf-pool-v3 F0 첫 풀이(note-300/3417 실행)
  - v11b 초기 묶음
  - 기타 `self-note-single-20261105/` 아래 원본 모델 생성 기록
- 같은 그림 해시·문항 ID로 연결한다. 몇 문항에 사전 기록이 있는지 보고한다.
- 점수 방향:
  - 원본이 틀렸고 채점 가능 → 높음 (교정 학습 대상)
  - 원본이 맞았지만 풀이가 길다 → 보통
  - 원본이 아주 짧게 맞혔고 쉬운 출처 → 낮음
  - 원본이 형식 붕괴·무한 반복 → 보통 (끝맺기 학습 대상)
- 기록이 하나뿐이라 잡음이 크다. **가중치로만** 쓰고 단독 제외 사유로 쓰지 않는다.

## 9. 학습 순서 (`order.json`)

- **기본 규칙** (전체 학습 설계 문서가 연구 결과로 바꿀 수 있음):
  1. 16문항 묶음마다 출처 비율이 전체 비율과 비슷하도록 **층화 교차**한다. 특정 출처가 뒤쪽에 몰리는 것(이전 3,417 실행의 문제)을 막는다.

  3. 같은 출처 안의 순서는 `sha256("v16b-order:" + problem_id)` 오름차순이다.
  4. 쉬운 것에서 어려운 것으로 가는 단계식 커리큘럼은 쓰지 않는다. 조사 결과 고정 난이도 순서는 무작위보다 나쁜 경우가 있었고, 넓은 벤치마크(MMMU)에서 순서 효과의 근거는 없었다(`/home/jang2/mmdl-artifacts/self-note-single-20261105/v16b/design-research-20261115/C_literature.md` §1).
  5. **권장 구현: "2단 고른 간격"**(같은 폴더 `V_final.md` §4). 출처 안에서 (사전 정오 W/C/없음, 긴 풀이 위험) 층을 `sha256("v16b-order:"+problem_id)` 순으로 놓고 `(순위+위상)/개수` 열쇠로 고르게 섞는다. 그렇게 만든 출처별 줄을 같은 방식으로 다시 섞는다. 검증된 재구현 기준은 같은 폴더의 `v/order_check.py`다.
- 순서 파일에는 묶음 번호, 문항 ID, 출처, 사전 난이도, 규칙 버전, seed, 입력 목록 해시를 넣는다.
