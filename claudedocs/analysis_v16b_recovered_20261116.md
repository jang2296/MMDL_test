평균 절대 log-ratio의 최대는 약 0.02295, IS clipping 비율 최대는 약 0.0003583이다.
현재 회수 기록은 ‘갱신이 자꾸 버려졌다’는 설명을 지지하지 않는다.
저장·재로딩 상태 일치 영수증도 존재한다. 이번에 모델을 다시 로딩한 것은 아니다.

그러나 본학습 첫 풀이 3,000개 모두가 직접 RL 신호를 준 것은 아니다.

- 양의 T1: 1,647개.
- 음의 T1: 1,095개.
- PG 제외: 길이 상한 251개 + UNVERIFIABLE 7개 = 258개.
- 이 258개에서 별도 C/N 학습으로 이어진 것은 0개.
- T1 전체 생성 3,355,419토큰 중 2,058,181토큰, **61.34%**가 이 PG 제외 응답에서 생성됐다.

따라서 ‘3,000문제를 전부 사용했으니 낭비 없이 오답을 학습했다’는 설명은 맞지 않는다.
다른 문항을 통한 공유 가중치 변화가 이 문항의 성능에도 영향을 줄 수는 있지만, 해당 응답의 직접 교정 신호는 없었다.

상위 탈락 사유는 검증 주장 없음 664, 누설 321, 반복 104, 관측 불일치 3, 비정상 종료 2다.

- 951개 중 rounding 필드는 정수 553·명시 null 194·누락 204였다.
- 279개에는 필수 필드 누락이 있었다.
- 950개는 원래 풀이의 정확한 비어 있지 않은 인용 구간 연결에도 실패했다.
- 유일한 정확한 인용은 단순 숫자 `27765`였고, 이것을 산술 등식 오류로 제시해 교정을 입증하지 못했다.

그러므로 정수 필드를 문자열로 바꾸는 수정만으로 검증된 교정이 확보되는 것은 아니다.
프롬프트가 요구한 복잡한 오류 계약을 실제 모델이 생성하지 못했고, 검증 근거의 범위도 좁았다.
형식 실패·근거 부족을 자연어 설명 전체의 거짓으로 취급해서는 안 된다.

누설 검사에도 재검토 후보가 있다. STEM 탈락 87개 중 19개는 문제에 이미 있는 어간, 6개는 모든 보기에 있는 어간이었다.
예를 들어 자기장의 힘을 묻는 문항에서 일반적인 force 설명이 `forc`로 차단됐다.
이는 개별 오탐 후보이지 모든 탈락 노트를 받아도 된다는 근거가 아니다.

## 7. 재풀이 SFT는 정답을 얼마나 버렸나

666회 재풀이 중 정답은 **192개**, 그 외 결과는 474개였다.
실제 학습 C는 16개, 7,275토큰이다.

| 탈락 사유 | 수 |
|---|---:|
| A2_NOT_ADMISSIBLE | 486 |
| 256토큰 미만 | 136 |
| 상한 길이 초과 | 12 |
| 교훈 누설 | 7 |
| 교훈 복사 | 5 |
| 검토 참고 문구 | 2 |
| 이미지 전용 회피 | 1 |
| 답 부정 | 1 |

A2_NOT_ADMISSIBLE 486개는 비정답 462개와 정답이지만 형식·반복 등으로 탈락한 24개로 구성된다.
나머지 비정답 12개는 길이 상한 초과로 분류됐다(잘림 8·복수답 3·오답 1).
136개는 모두 최종 정답 판정을 받았고, 길이는 34–254토큰, 중앙값 102토큰이다.
다만 길이 검사 다음에 오는 과정 모순·최종 일관성 검사는 실행되지 않았으므로 전부 학습 가능한 자료로 인증할 수 없다.

- 116토큰 도형 재풀이는 중점 연결 정리와 2×5=10을 명시했지만 하한에서 탈락했다.
- 100토큰 그래프 재풀이는 최종 선택은 맞아도, 나열한 경로에 정점 1이 두 번 나오면서 정점이 반복되지 않는다고 주장했다.
- 이미 학습된 긴 음악 C에서도 같은 조표를 서로 다르게 설명하는 내부 모순 사례가 있었다.

**256토큰은 풀이의 정확성을 보장하지 않고, 정답인 최종 선택 역시 전체 과정의 정확성을 보장하지 않는다.**
짧은 풀이 일괄 수용이나 긴 풀이 자동 인증 모두 해법이 아니다.

## 8. A1 경로 제거와 기존 능력 보존

본학습 첫 풀이 정답 1,647개 중 현재 helper를 사용한 v15식 CPU 관문 후보는 448개였다.
이는 반사실적 후보 집계이며 실제 새 학습량·풀이 내용의 정확성 인증은 아니다.
다른 정답 행은 짧음 1,019·반복 165·길이 초과 10·답 부정 5로 분류됐다.

v16b 본학습은 T1→RL만 만들고 A1을 만들지 않는다.
PREP_SELF 25개는 별도 준비 문항이며 본학습의 정답 풀이를 계속 학습하는 경로가 아니다.
따라서 v15에서 존재했던 정답 풀이 SFT의 보존 효과가 v16b에도 유지됐다고 가정할 수 없다.
하지만 A1 부재가 하락의 원인이라는 대조 증거도 아직 없다.

원본 보존 KL은 첫 4개 응답 위치에만 적용되고 전체 응답 KL 계수는 0이다.
응답 도입부를 보존하는 것만으로 이후 수치 읽기·추론·최종답 형식까지 보존됐다고 볼 수 없다.
학습 샘플링은 top-p 1/top-k 0, 평가는 top-p .8/top-k 20으로 다르다.
이 차이는 설계 선택이며 그 자체가 버그나 이번 하락의 증명은 아니다.

## 9. 평가 지연은 별개의 실행 문제

회수 backend 기록에서 첫 시도 동시 요청 32, 두 번째 10을 확인했다.
첫 시도 로그의 KV cache 용량은 444,416토큰이다.
32개가 출력 상한 32,768토큰에 접근하면 출력만 1,048,576토큰으로 그 용량을 넘는다.
단, 이 계산은 최악 조건의 수용 능력 검사이며 모든 요청이 실제로 그 길이에 도달했다는 실측은 아니다.

기존 운영 기록은 앞쪽 긴 문제의 몰림과 선점·재계산 반복을 지연 원인으로 기록한다.
회수 로그에서 용량·동시성·59문항 뒤 완료 기록 단절은 확인했지만, 이번 분석에서 선점 횟수 전체를 독립 복원하지는 못했다.
KV 부족 때 재계산이 지연을 늘릴 수 있다는 동작은 [vLLM 공식 문서](https://docs.vllm.ai/en/stable/configuration/optimization/)와 일치한다.

이 실행 문제 때문에 전체 점수를 얻지 못했다. 이것을 모델 정확도가 떨어졌다는 증거로 사용하지 않는다.
이번 분석은 평가 재시작이나 동시성 변경을 수행하지 않았다.

## 10. 현재 근거로 말할 수 있는 원인과 한계

| 판단 | 근거 수준 |
|---|---|
| 감시 응답에서 내용 오류와 최종답 형식 손실이 함께 발생 | 원문·재채점·일부 이미지로 확인 |
| 실제 학습·갱신은 작동했고 HOLD/IS 제외가 원인은 아님 | 실제 영수증으로 확인 |
| 오류 원인과 수정 내용을 학습하는 N 목표는 확보되지 않음 | 전체 노트·실제 N 목표로 확인 |
| 틀린 관측의 음의 신호가 마스킹으로 매우 좁아짐 | 실제 토큰 통계로 확인 |
| 유용할 수 있는 정답 재풀이가 길이 하한에서 제외 | 정답/길이 수치·표본 원문으로 확인 |
| 일부 수용 C의 과정에도 모순이 남음 | 목적 표본의 원문 확인, 전체 오류율 아님 |
| A1 부재·좁은 KL·분포 차이가 하락에 기여 | 가설, 대조 실험 없음 |
| v16b MMMU 전체가 원본/v15보다 낮음 | 현재 부분 결과로 판정 불가 |
| RL+SFT 자체나 65점 목표가 불가능 | 입증되지 않음 |

진단상 핵심은 ‘작동하지 않은 RL’보다 **교정할 근거·교정 대상·보존할 정답 풀이가 손실 함수에 연결되는 범위가 좁았다는 것**이다.
동시에 수용된 정답 풀이에도 과정 오류가 남을 수 있었다.
이 구조는 개선 실패와 일부 성능 손실의 유력한 설명이지만, 점수 기여를 확정한 인과 분석은 아니다.

## 11. 다음 변경의 우선순위 — 이번 분석에서 실행하지 않음

1. 노트 생성 전에 원 주석·연산 규칙으로 실제 검증 가능한 오류 계약이 있는지 확인한다. 없으면 그 문제에서 노트 교정 학습이 가능하다고 계산하지 않는다.
2. 원문 인용과 오류 계약을 모델이 실제로 작성할 수 있는지 작은 외부 학습 표본에서 확인한다. AI가 노트를 대신 고쳐 정답 라벨로 넣지 않는다.
3. 136개 짧은 정답 재풀이에 남은 검사를 적용하고 내용 있는 풀이와 잘못된 과정을 구분한다. 기존 결과의 기준을 소급 바꾸지 않는다.
4. 본학습 정답 T1의 별도 SFT 보존 경로를 제한적으로 복원하는 후보를 검토한다. 모든 오답을 SFT로 바꾸지 않는다.
5. 음의 관측 신호 194토큰이라는 실측을 기준으로 토큰 선택 규칙을 검토한다. 강도를 무작정 올리거나 마스크를 일괄 제거하지 않는다.
6. 평가 실행의 최악 문맥 수용 능력과 장시간 요청 처리를 별도로 검증한다. 평가 미완료를 학습 정확도 문제와 섞지 않는다.
7. 다음 방법의 효과는 기존 부모 모델과 같은 외부 문항의 첫 풀이로 비교한다. 이번에 분석한 감시 집합은 이미 개발 판단에 사용됐으므로 새로운 독립 확증 집합으로 포장하지 않는다.

## 12. 검증 범위

부분 MMMU와 감시 응답의 CPU 재채점, 회수 파일 해시, 실제 학습 행·갱신 통계, 노트/재풀이 원문, 목적 표본 이미지까지 확인했다.
원본 실행의 반복 표본, 전체 MMMU, 손실 항별 제거 실험, GPU 재로딩, 내부 Vision 단독 책임, 전체 풀이의 전문 내용 정확성은 확인하지 않았다.
optimizer runtime.pt와 준비 종료 체크포인트는 회수 대상에서 제외되어 실제 optimizer 최종 LR이나 해당 체크포인트를 새로 실행해 확인하지 못했다.
새 다운로드·GPU·클라우드·학습·평가·공개 게시·코드 수정은 하지 않았다. 분석 스크립트와 이 보고서, PROJECT_STATUS 기록만 추가했다.
