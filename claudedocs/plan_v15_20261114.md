## 4. 포드 실행 1회

### 4.1 장비와 조건

- **장비:** 커뮤니티 A100 80GB(시간당 1.50달러 이하).
  - 이어받기는 v14와 같은 용량 설정을 요구한다.
  - v14 갱신 단계가 이미 약 49GB를 썼다.
  - 시각 학습을 모든 행으로 늘리면 48GB인 A40은 위험하다.
- **시작 조건:** 실제 잔액이 14.1달러 이상이고 가격이 시간당 1.50달러 이하일 것.

### 4.2 사전 점검 (학습 전)

1. 업로드 파일 해시 확인.
2. 감시 규칙 자체 시험.
3. 판정 도구 점검 사례.
4. 조정층 사전 점검 PF0~PF5(2~3분).
5. 첫 v15 묶음의 재생 차이 확인.

어느 하나라도 실패하면 학습하지 않고, 기록을 회수한 뒤 포드를 삭제한다.

### 4.3 시간과 비용 (추정, 측정 전)

| 단계 | 예상 시간 | 비관적 시간 |
|---|---|---|
| 설치·업로드·사전 점검 | 0.3h | 0.65h |
| 학습 23묶음 (묶음당 10~13분 추정: 다시 풀기, 시각 학습, 조정층 적용 부담 포함) | 4.0h | 5.0h |
| 재로딩·내보내기·사전등록·평가 사전 점검 | 0.3h | 0.4h |
| 앞 절반 450문항 | 1.7h | 2.0h |
| 판정 도구 (v15와 같은 문항의 B2) | 0.15h | 0.75h (상한) |
| 회수·해시·삭제 | 0.2h | 0.3h |
| **앞 절반에서 멈춤** | **약 6.6h = 9.2달러** | 약 9.0h = 12.5달러 (상한) |
| 뒤 절반까지 | **약 8.3h = 11.5달러** | 남은 시간이 부족하면 뒤 절반은 하지 않음 |

포드 수명 상한은 9.0시간(12.51달러)이다. 잔액 14.83달러면 최소 2.32달러가 남는다.

**사용자가 앞서 말한 7.5~9.5달러보다 높다.** 그림 학습과 다시 풀기 3번이 묶음 시간을 늘리기 때문이다.

### 4.4 중단 규칙 (미리 고정)

1. 사전 점검 실패 → 학습하지 않음.
2. 감시 규칙 발동 → 묶음 경계에서 정지. 56묶음 이상이고 재로딩이 통과했을 때만 평가한다.
3. 메모리 부족 등 실패 → 해상도·토큰·정밀도를 낮춰 다시 하지 않는다.
4. 앞 절반 V8 281 미만 → 멈춘다. 결과는 450문항 개수만 보고하고, 백분율이나 900문항 환산은 하지 않는다.
5. 뒤 절반은 남은 시간이 앞 절반 실측의 1.1배 + 20분 이상일 때만 한다.
6. 판정 도구는 V8 결과가 저장된 뒤에만 시간 상한 안에서 돌린다. 점검 사례에서 잘못된 인정이 1건이라도 나오면 점수를 내지 않는다.
7. 평가는 체크포인트 하나에 한 번이다.
8. 해시를 확인한 로컬 회수 전에는 포드를 삭제하지 않는다.

## 5. 보고 방식

- **V8 점수와 V8+보완 점수를 나란히 쓴다.** 과제 점수 558과 진행 판정은 V8 기준이다.
- **비교 대상과 지표:**
  - 같은 문항의 B2·v13·v14 체크포인트 41 대비 득실과 검정 값.
  - 한 번 실행의 표준편차 7.7.
  - 반복 문항의 끝낸 수와 맞힌 수.
  - 시각 기울기 크기.
  - 다시 풀기 시도별 통과 수.
- **반드시 밝힐 것:**
  - v14 체크포인트 41의 결과(279/450)를 본 뒤 정한 실행이라는 점.
  - 평가 때 조정층 적용 방식이 이전 판(합친 16비트)과 달라 점수 비교에 두 효과가 섞인다는 점.
  - 감시 규칙을 바꾼 이유.

## 6. 남은 위험

1. vLLM 0.11에서 조정층을 따로 적용하는 경로는 이 프로젝트에서 처음 쓴다. 로컬 작은 모델 시험과 포드 사전 점검이 잡지 못하는 오류가 있을 수 있다.
2. 모든 행 시각 학습의 메모리·시간은 미측정이다. 첫 묶음이 수용 시험이다.
3. 이어받은 체크포인트 41의 조정층을 "온전한 세기로" 생성에 쓴 적은 없다. v14는 언어 쪽 약 45%, 시각 쪽 약 12%만 반영된 상태로 생성했다. 첫 묶음의 행동이 이 이유만으로 바뀔 수 있다.
4. 시각 조정층의 옵티마이저 상태는 12번 갱신분뿐이고, 남은 학습률이 낮다.
5. 감시 기준인 v13 기록은 학습용 채점 v1로 채점됐다(v15는 v2). 그래서 규칙이 덜 민감해지는 방향으로만 치우친다.
6. 비용이 상한에 닿으면 뒤 절반을 하지 못할 수 있다.

## 7. 구현 순서 (사용자 명령 후)

- **1차:** T1 (단독, 다른 작업이 의존)
- **2차 (동시):** T2, T4, T5 — 파일이 겹치지 않게 나눈다. `single_campaign.py`의 `lora=` 한 줄은 T4가 맡는다.
- **3차:** T3 (T2와 같은 `single.py`)
- **4차 (동시):** 평가 커밋 E1~E5와 C, 포드 스크립트
