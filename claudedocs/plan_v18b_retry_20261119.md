## 4. 담당과 인계

1. Codex가 A와 B를 독립적으로 수정한 뒤 예행을 연결한다. 로컬 인계물은 변경 목록, CPU 회귀, 같은 실패 시험의 두 로그, 수정본 전체 C1 결과, 감시 1회 토큰 수·시간, §5.1 완주 설정의 계획 생성 결과다. 예행 시간과 정확도 감시 비용에는 측정 환경을 붙인다.

4. 공식 평가는 선정된 닫힌 저장본 하나로 진행한다. 최종 기록에 학습 문항 수·정산 슬롯·검증된 노트의 실제 갱신 기여·MMMU 완료 문항 수·V8·별도 보완 점수·회수 해시·종료 시각을 적는다. 900개가 끝나지 않았다면 전체 점수는 미완료로 남긴다.

다음 공식 학습은 `one_pod`, `limit_action="warn"`, `budget_limit_usd=null`, `training_cutoff_seconds=null`과 첫 과금 기준 계획 시간 86,400초 이상을 사용한다. 과거 봉인본의 중단 설정은 그 실행을 해석할 때 사용한다. 188묶음과 지연된 3슬롯을 완료한 뒤 최종 모델을 정한다. 기술적인 무결성 실패와 기존 8K 정확도 중단은 각각 원래 사유로 기록한다.
