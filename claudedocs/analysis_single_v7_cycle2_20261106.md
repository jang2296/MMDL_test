3. **A1(+1)이 추측이나 틀린 근거의 풀이를 강화합니다.** 18개 중 3–5개가 해당합니다(010883, 010884, 000006, 007962 등). 3,500 규모에서는 행 대부분이 A1, 즉 자기 정답 모방이 됩니다. 버전 2에서 이런 학습은 미학습 541 대비 544(순 +3, p 0.86)로 차이가 없었습니다.
4. **누설 검사에 구멍이 있습니다.** 4건이 통과했습니다: 003489 'metallic', 010633 'bronchial tree segments', 006549 '동률', 000552 'decimals'. 부분 문자열, 어간, 의미 수준의 누설을 잡지 못하고, 006549는 두 회차 연속 학습 행이 됐습니다.
5. **B 행이 'Cause: NONE'과 정답에 끼워 맞춘 사실을 학습시킵니다.** 평가 입력(P0)에는 노트가 없으므로 영향은 간접적이지만, 같은 조정층을 공유합니다.
6. **형식 A2가 P0에 'Final Answer: 숫자만' 습관을 심습니다.** V8은 최종답 추출기를 쓰므로 영향은 작다고 보지만, 방향은 확인하지 않았습니다.
7. **작은 결함**: 'as per' 부분 문자열 오탐(000552), 반복 필터 오탐 의심(005000, 000564), 노트 1024 상한(004304 하나). 음악 4문항(ssmr)의 오선 줄 이름은 지식 공백이라 노트로 고쳐지지 않습니다.

## 5. 권고: 3,500문항 본실행은 지금 보류, 수정 1회 더

**보류 이유**: 64문항에서 깨끗한 실제 교정은 0개, B는 10개 중 8개가 NONE, −1은 13개 중 9개가 의심스럽습니다. 같은 비율을 단순 비례하면(추정) 3,500문항에서 다음과 같습니다.
- A2 약 550개, 대부분 형식 행
- B 약 550개, 그중 약 440개가 NONE
- −1 약 710개, 그중 약 490개가 의심 보상

1판·2판 결과(537, 544 < 558)를 되풀이할 가능성이 큽니다.

**다음 회차 최소 수정** (규칙 유지: 모델 자신의 글만, 문항당 T1·노트·재풀이 각 1회, 답 고르기 없음, 평가 P0 고정)
1. **학습 채점기를 V8과 같은 최종답 추출로 바꾸고, 표기 정규화를 미리 고정합니다.**
   - 대상: 끝 단위어, '^\circ', '%', 'thousand', 'parts', 숫자 단어 'three', '\boxed{}', '\sqrt{}', 'a%-b%' 범위, CLEVR 재질 동의어(metal/metallic).
   - 새 채점 버전으로 분리하고, GPU를 쓰기 전에 2회차 저장 출력 전체를 CPU로 다시 채점해 이전/새 차이를 보고합니다.
   - 기대 결과: 000547, 004301, 000555, 000567, 000580, 000592, 005648, 003489는 정답이 되고, 004300, 004302, 004304는 확정 오답(보상 0)이 됩니다.
   - 000552(75 vs 0.75)와 010573(X-Ray)은 표기가 모호하므로, 기준을 완화하지 말고 미판정으로 제외합니다.
2. **노트 입력에 채점기가 읽은 값 한 줄을 추가합니다.** 예: 'The grader read your final answer as: …'.
   - 프로그램 검사 추가: 채점이 WRONG이거나 미확정인데 'Cause: NONE'이면 노트를 받지 않습니다(B 행 없음).
   - 최종답 미확정이나 잘림이면 원인은 NO_FINAL_ANSWER만 허용합니다.
3. **누설 검사를 넓힙니다.** 정답이나 보기 내용의 4자 이상 어간이 교훈 단어 안에 들어 있으면 차단합니다(metal⊂metallic, bronch⊂bronchial). '동률'이나 '소수 표기' 같은 의미 수준의 누설은 프로그램으로 못 잡으므로, 남는 위험으로 보고합니다.
4. **A1·A2 수용에 고정 문구 차단을 넣습니다.** 대상 문구: 'question is incomplete', 'not explicitly drawn', 'mistake in the problem', 'question is flawed', 'mislabel'. 010884, 000006, 004299, 010185가 걸립니다. 답이 맞아도 +1 대신 0입니다.
5. **작은 수정**: 'as per' 검사를 단어 경계 기준으로 바꾸고, 반복 필터는 005000과 000564로 확인합니다.
6. **바꾸지 않을 것**
   - 재풀이 지시: 형식 문제를 푼 유일한 요인입니다.
   - 보상 v4 구조
   - 'outside knowledge / only visible details' 구별 문구: 되살리지 않습니다. 3판(V3)에서 '이미지만 보라'는 얼버무림을 가르쳤고, 2회차에도 010185 'directly from the image … not … common knowledge', 008761 'visual cues can be misleading' 같은 교훈이 남아 있습니다.

**3회차 통과 기준** (미리 고정)
- CPU 재채점 차이가 위 기대와 일치할 것
- GPU 64문항에서: 내용이 맞는 답의 −1이 0개, 확정한 답의 '미확정' −1이 0개, B의 'Cause: NONE'이 0개, 교훈을 언급하는 A2가 0개일 것
- 이 위생 기준을 넘긴 뒤 깨끗한 실제 교정 A2 수를 그대로 보고합니다. 그 수가 또 0–1개라면, 본실행은 사실상 자기 정답 모방(A1) 학습이 됩니다. 버전 2 결과(544)로 보아 558을 넘기 어렵다고 알린 뒤, 300문항 시험으로 갈지는 사용자가 정합니다.

**비용**: 블록 4개 × 평균 5.8분이면 약 23분에 준비 시간이 더해집니다(시간당 1달러 미만 GPU). 1번 정규화의 효과와 3·4·5번 필터는 저장된 출력으로 GPU 없이 먼저 검증할 수 있습니다. 2번(노트 입력 변경)과 1번이 새 노트·재풀이에 미치는 영향만 GPU가 필요합니다.
## 6. v8 구현 후 기준 수정 (2026-11-07, 주 에이전트 결정)

Fable 감사(FAIL)에서 §5의 CPU 기준 일부가 맞지 않는다고 지적했다. 확인 결과와 결정은 다음과 같다.
- 005648('There are three symbols in the legend.'), 000553·005647(답 선언 없음), 010185(MCQ에서 B를 쓴 뒤 A로 고침)은
  **MMMU V8 평가 채점기도 오답으로 처리**한다(감사가 `final_answer_parser_v8.score_response`로 확인). 학습 채점이 평가와 같으므로
  이 형식의 −1은 의도적으로 유지한다. §5의 "내용이 맞는 답의 −1 0개"는 "**MMMU V8도 오답으로 보는 형식에만 −1**"로 바꾼다.
- 000552('75' 대 0.75): ×100 또는 ÷100에서만 맞는 숫자는 UNVERIFIABLE(보상 0, 노트 없음)로 제외한다. 정답으로 바꾸지 않는다.
- 010573('X-Ray' 대 'chest X-ray'): 포함 관계 규칙은 부분 답(Lung 대 Right lung)까지 제외할 수 있어 넣지 않았다. INCORRECT로 남는다.
- Cause NONE 노트는 다시 풀기를 막지 않고 **B 행만** 막는다(감사 추정: 다시 풀기 단계에서 막으면 A2가 10개에서 약 1개로 줄어듦).
  노트 지시문에서 NONE과 "잘못이 없으면" 문장을 뺐다(노트는 오답에만 쓰므로).
- 저장된 1·2주기 출력 재채점(v7→v8): 주관식 첫 풀이에서 오답→정답 13, 미확정→확정 오답 6, 오답→제외 2. MCQ는 변화 0.
  사람이 아닌 AI가 오답으로 판정한 목록의 문항이 정답으로 바뀐 경우는 0이다.
