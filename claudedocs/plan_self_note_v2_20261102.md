## 1. 판정 기준

- **주 판정:** 학습 모델을 MMMU validation 900문항으로 1회(seed 3407) 풀어, V8 정답 수가 **558/900(62.00%)을 넘는지**만 본다.
- **평가 조건:** B2(62점) 설정(`configs/eval/mmmu_val_v8.yaml`)과 **최대 토큰만 다르고 나머지는 같게** 한다.
  - 같게 하는 것: P0 프롬프트, `team-final-answer-v8`, 생성 설정(temperature 0.7 / top_p 0.8 / top_k 20 / presence 1.5), 문항별 seed, vLLM 0.11.0
  - 다른 것: 최대 토큰 8192(B2는 32768). 이미지 262144–1310720(B2는 1003520–4014080). 동시 처리 수는 메모리에 맞춰 자동으로 정한다(B2는 2).
  - `[사용자 2026-11-02]` "이미지 크기는 고해상도일 필요는 없어, 이전 실험에서도 크게 점수가 바뀌지는 않았으니까" → 1판 이미지 값을 유지하고, 1판 평가 변형 `mmmu-val-v8-8k-seed3407-v2`를 그대로 쓴다. 예전 기록(R2 554 → B2 558)도 이미지 확대 효과가 작았다.
- **해석 주의:**
  - 8192는 32768보다 불리하다. B2 응답에서 8192를 넘은 120개 중 정답은 14개였다. 그래서 8K로 62점을 넘으면, 같은 모델을 32K로 풀어도 넘는다고 볼 근거가 생긴다. 다만 그 자체가 개선 입증은 아니다.
  - 1회 결과라서 실행 간 흔들림(표준오차 약 1.6점)이 남는다. 62점을 1~2점 넘는 정도는 우연과 구분되지 않는다고 함께 쓴다.
- **학습 전 모델 참고값:** 같은 변형·같은 GPU 종류(RTX 6000 Ada, 동시 40)로 이미 잰 1판 F0 seed 3407의 900문항 541(60.11%)을 참고값으로 쓴다(새로 돌리지 않음). 다른 GPU에서 평가하게 되면 F0도 다시 잰다.

## 2. vLLM 재현성

- 설치된 vLLM 0.11.0을 확인했다. `VLLM_BATCH_INVARIANT`는 **없다**(설치본 전체에서 찾지 못함). 이 기능은 더 새로운 버전에 있으며, 쓰려면 평가 환경을 바꾸는 새 protocol이 된다. 이번에는 쓰지 않는다.
- 이미 적용된 것:
  - 수집(`collect.py`)은 `VLLM_ENABLE_V1_MULTIPROCESSING=0`과 문항별 `SamplingParams(seed=…)`를 쓴다.
  - 평가 backend도 문항별 seed를 쓴다.
- 이번에 추가할 것:
  - 평가에도 `VLLM_ENABLE_V1_MULTIPROCESSING=0`을 적용한다(엔진 seed는 `src/mmdl` 변경이 필요해 적용하지 않음, 문항별 seed는 적용).
  - 런포드 10문항 확인 때 같은 10문항을 동시 처리 수 1과 자동값으로 두 번 풀어 토큰 일치율을 재고 기록한다.
- 같은 seed라도 GPU 종류가 다르면 결과가 다르다. B2는 RTX 3090, 이번은 A40 또는 6000 Ada다.

## 3. 학습 자료 흐름 (3,417문항, 고정 목록 그대로)

| 단계 | 내용 | 정답 노출 |
|---|---|---|
| T1 풀기 | 1판 T1 3,417개를 그대로 재사용(같은 문항·seed·이미지 값·8192토큰, 정답 없이 1회) | 없음 |
| V8 채점 | 별도 채점 서비스 | (채점기만) |
| 노트 v2 | 문제·이미지·T1·채점 결과·정답을 보고 노트를 쓴다. **고쳐 쓴 풀이는 쓰지 않는다.** 제목은 What the image shows / Image reading / Cause / What went wrong / Lesson. 8192토큰, 짧게 쓰라는 지시를 넣는다 | 있음 |
| 다시 풀기 | T1이 정답이 아닌 문항만 대상이다. P0 앞에 노트의 **Lesson 칸만** 붙여 1회 푼다. 정답·T1·채점 결과·What went wrong은 넣지 않는다 | 없음 |
| 힌트 누설 검사 | 정답을 아는 노트 단계에서 검사하고, 통과한 교훈만 `lessons.json`에 쓴다. 보기 기호 언급, 단독 정답 기호, 정답 보기의 단어(길이 무관, 대소문자·띄어쓰기·문장부호 무시), "answer is"류가 있으면 다시 풀지 않는다(거짓 양성 쪽으로 보수적) | – |
| V8 채점 | 다시 푼 답 | (채점기만) |

**학습 행**
- A1: T1이 정답이고, 정상 종료했고, 기준을 통과하면 T1 원문을 그대로 쓴다.
- A2: 다시 푼 답이 정답이고 기준을 통과하면 그 원문을 쓴다. **입력은 힌트 없는 P0**(평가 입력과 동일)다.
- B: 노트 프롬프트 → 노트 원문.
- 정답을 보고 쓴 풀이는 행으로 만들지 않는다.

**거르는 기준**
- 기존: 정상 종료, V8 정답, 32–4096토큰, 12토큰 3회 반복
- 추가:
  - 끝 3,000자 압축률 12% 미만이면 반복으로 보고 제외한다.
  - A2에 "lesson", "hint", "review", "earlier", "note"류 표현이 있으면 제외한다. 평가 때는 힌트가 없기 때문이다.

**경로:** 노트가 MISREAD라고 쓰면 Vision 조정층 + Merger + LLM 조정층, 그 외에는 Merger + LLM 조정층이다(자기 신고 그대로). 원본 가중치는 고정한다.

**토큰 한도 점검(결정 사항):** 노트와 다시 풀기에서 8192에 걸린 글을 "반복(압축률 기준)"과 "반복 아님"으로 나눠 보고한다. 반복 아님 비율이 크면 한도를 늘릴지 사용자에게 묻는다. 자동으로 늘리지 않는다.

## 4. 학습 설정 (1판 대비 변경)

- **순서:** 출처가 학습 내내 고르게 섞이도록 한다. 각 출처 안의 고정 순서는 그대로 두고, (출처 안 순위 ÷ 출처 크기) 순으로 정렬한다. 결과를 보기 전에 `item_order_v2.json`으로 고정한다.
- **갱신:** 갱신 1회에 16문항(1판 8)을 쓴다. 3,417문항이면 약 214회다.
- **학습률:** 10회 warmup 뒤 0까지 선형으로 줄인다(1판은 고정). LR 값(L 5e-5 / M 1e-5 / V 1e-5)과 LoRA 설정은 그대로다.
- **변형 비교 없음:** 방식 하나만 미리 등록하고 그대로 평가한다(MMMU로 고르지 않는다).

## 5. 런포드 실행

- GPU: RTX 6000 Ada(0.99달러/시) 우선, 없으면 A40. 같은 일 기준으로는 6000 Ada가 3.5배 빨라 더 싸다(1판 실측).
- 한 대여기에서 T1 → 노트 → 다시 풀기 → 행 → 학습 → 재로딩 → export → 평가(학습 모델, 학습 전 모델) 순으로 대기 없이 이어서 실행한다.
- 생성은 vLLM 동시 처리로 하고, 동시 수는 메모리에 맞춰 자동으로 정한다. 학습은 생성이 끝난 뒤 묶음으로 한다. 한 그래픽카드에서 생성과 학습을 동시에 하면 메모리를 나눠 써서 둘 다 느려지므로 하지 않는다.
- 결과는 15분마다 노트북으로 내려받고 해시를 확인한다. 끝나면 내려받기 → 해시 → 삭제 → 목록 0 → 청구 조회 순으로 정리한다.
